# Shinra Tensei

**Parallel IMAP mailbox archiver for Windows with built-in Outlook PST export.**

Shinra Tensei downloads several mailboxes at once from any IMAP server, keeps them in a local archive, lets you browse the messages right inside the app, and exports each mailbox to a standalone Outlook `.pst` file. The interface and workflow are inspired by MailStore Home/Server.

PST files are generated by the program itself according to the open Microsoft [MS-PST] specification. **Outlook is not required** for export: it does not need to be running or even installed.

> The interface is available in **English and Russian** (toolbar → "Settings" / "Настройки" → "Язык / Language").

## Features

### Download
- Several mailboxes in parallel; the number of simultaneous downloads is configurable.
- Tick several mailboxes with checkboxes (click the ✔ column header to tick or clear all) and run, export or delete them together.
- Right-click context menu: start download, export to PST, view messages, edit mailbox, delete mailbox.
- Progress shown as `downloaded / total (NN%)` for every mailbox.
- Per-mailbox settings: e-mail, IMAP server, port, connection security (SSL/TLS, STARTTLS, none), login and password.
- Per-mailbox storage folder for `.eml` files (or the shared archive folder). When the folder is changed, already downloaded mail can be moved there.
- **Accept all certificates** option for expired or self-signed certificates, hostname mismatches and legacy TLS servers.
- Date range: all time, or from/to a specific date.
- All folders, or a single selected folder (the folder list is loaded from the server; non-Latin folder names are supported).
- **Error handling per message**: if a message fails, the app asks whether to *Skip*, *Skip all errors for this mailbox*, *Retry* or *Stop*. Dropped connections are re-established automatically (up to 3 attempts).
- **Incremental**: re-running a mailbox downloads only new messages.
- Messages are fetched from the server in batches (up to 100 messages or 16 MB per command), not one by one.
- **Downloading starts at once**: a folder is prepared in parts of 1,000 messages, and each part's batches start downloading straight away.
- **How to download mail** is chosen on the second page of the mailbox window ("Next"), with the pros and cons of each option:
  - **one or several connections** (2–10): batches are downloaded at the same time, which is faster on servers that limit the speed of one connection;
  - **duplicates**: a message with the same Message-ID and size as one already in another folder of the mailbox (such as Gmail's "All Mail") is not downloaded again. "Automatic" looks for them only in mailboxes with "All Mail"; you can also always look or never look.

### Built-in viewer
- Tree of mailboxes and folders with message counts.
- Message list with **sent date** (from the message header) and **received date** (server INTERNALDATE), sender, recipients, subject, size and an attachment indicator.
- Sorting; search everywhere or only in sender, recipients, subject or attachment names (optionally in message text too).
- Filters: date range by sent or received date, only messages with attachments, minimum size.
- Preview of HTML and plain-text messages, including inline images. Remote content is never loaded.
- Save attachments and `.eml` files, view raw headers, open messages in the default mail client.

### PST export
- One `.pst` file per mailbox, preserving the folder structure (`INBOX` becomes the Inbox folder).
- Exports subject, sender, To/Cc recipients, sent and received dates, plain-text and HTML bodies, attachments of any size, original transport headers and read/unread state.
- **Duplicates are not written** by default (the same message in several folders, such as Gmail's "All Mail"): the message stays in its label folder, and "All Mail" keeps only messages without labels. A checkbox in the export window; the report shows how many were skipped.
- Optional **PST password**: up to 15 characters, ASCII only (an Outlook limitation).
- Configurable part size (0.5–50 GB, default 10 GB); larger mailboxes are split automatically into several parts. Messages are written in received-date order, so each part covers a continuous period.
- **Export report** saved next to the PST (`<e-mail>_отчёт.txt`): for every part — file size, message count, period, and each folder with its message count and date range.
- The export window is independent: downloads and the main window keep working while it runs, and several exports can run at once.
- Export progress: per-mailbox and overall bars with message counts and percentages.
- **Self-verification**: after writing, every file is re-read by an independent PST parser that checks CRCs, signatures, B-trees, heaps, property and table contexts, and per-folder message counts.

### Other
- English and Russian interface; the first start picks the Windows language. Dates, numbers, PST folder names and the export report follow the chosen language.
- Light, dark and system themes (toolbar → Settings).
- Mailbox passwords are stored encrypted with Windows DPAPI (optional).
- Detailed log with a tab per mailbox (plus an "All" tab); PST export lines go to the mailbox tab too. Also saved to log files.

## Download / Build

### Option 1: GitHub Actions (no local Python needed)
Push the repository to GitHub. The `Build Shinra Tensei.exe` workflow runs the tests and builds the executable automatically. Download it from **Actions → latest run → Artifacts**.

To publish a release, push a version tag: `git tag v0.13.0 && git push origin v0.13.0`. The workflow builds the app and publishes `Shinra-Tensei-<version>-win64.zip` under **Releases**, with that version's section of the changelog as the description.

The app is a folder (`Shinra Tensei.exe` plus `_internal`), not a single exe: a single-file exe unpacks Python and Qt to `%TEMP%` on every start, and the antivirus scans every DLL again, so it opened several seconds slower. Unzip the folder anywhere and run `Shinra Tensei.exe`; settings stay in `%APPDATA%` as before. Build settings live in `shinra.spec`.

### Tests
`python -m unittest discover -s tests -t .` checks message parsing (Rust and Python agree, corrupted messages never crash), PST writing and self-check, downloading from a fake IMAP server (batches, dropped connections, quirky servers, duplicates), and the viewer index and filters. With `SHINRA_PURE_PYTHON=1` the same tests check the Python code. GitHub Actions runs them on every push in both modes.

### Option 2: Build locally on Windows
1. Install [Python 3.10+](https://www.python.org/downloads/) and tick **"Add python.exe to PATH"**.
2. Run `build.bat`.
3. The result is the `dist\Shinra Tensei` folder; run `Shinra Tensei.exe` inside it. Copy the whole folder, not only the exe.

### Option 3: Run from source
```bat
pip install -r requirements.txt
python app.py
```

### Native core (Rust, optional)
Mail download and PST export run on a native core written in Rust (`native/`).

The core does the whole download: connecting (SSL/TLS via rustls, STARTTLS, unencrypted), signing
in, folders, preparation, batches, several connections, reconnects, duplicate detection and writing
messages to the archive. Stop takes effect at once. If a server only knows TLS 1.0/1.1, the download
switches to the Python module by itself.

Export: the core parses `.eml` files, writes the PST and runs the self-check about 6× faster than
the Python code, and several exports running at once really use several CPU cores. The PST files it
writes are byte-for-byte identical to the Python writer's.

The message viewer stays in Python (PySide6), but the core also builds its folder index, on several
threads and about 15× faster.

- GitHub Actions builds it automatically. `build.bat` builds it when [Rust](https://rustup.rs) is
  installed and otherwise skips it.
- From source: `pip install ./native` (needs Rust).
- Without the module, or with the environment variable `SHINRA_PURE_PYTHON=1`, the app uses the
  pure-Python code as before.
- `python native/check.py "<archive>\<e-mail>"` compares both versions on a real mailbox: message
  parsing, PST bytes and the self-check.

## Usage

1. **Add mailbox**: enter the e-mail address, server, protocol and credentials. Use *Check connection* to test the settings. *Next* opens the page where you choose how to download mail (connections and duplicates).
2. Choose the **period** and either **all folders** or a single folder.
3. Tick the mailboxes you need and click **Run selected** (or **Run all**), or use the right-click menu. Progress, counters and errors are shown per mailbox.
4. Open **View messages** to browse what has been downloaded.
5. Click **Export to PST**, choose the mailboxes, the output folder and an optional password.
6. In Outlook: **File → Open & Export → Open Outlook Data File** and select the generated `.pst`.

## Data locations

| What | Where |
|---|---|
| Archive (one `.eml` per message) | `Documents\Shinra Tensei\Archive\<e-mail>\<folders>\` (configurable) |
| Settings | `%APPDATA%\Shinra Tensei\config.json` |
| Logs | `%APPDATA%\Shinra Tensei\logs\` |
| PST output | `Documents\Shinra Tensei\PST\` (configurable) |

Settings from the previous project name (*MailArchiver*) are migrated automatically on first start.

## Project structure

```
app.py                  Main window, entry point
core/
  imap_client.py        IMAP connection, folder listing, search, fetch
  imap_utf7.py          Modified UTF-7 codec for IMAP folder names
  downloader.py         Per-mailbox download: batches over one or more connections, reconnects, skip-on-error
  storage.py            Local .eml archive layout
  mailparse.py          Robust MIME parsing (legacy Cyrillic encodings, attachments)
  htmlclean.py          Cleans HTML messages before the viewer shows them (hidden text, remote pictures, scripts)
  mail_index.py         Cached message index for the viewer
  pst_writer.py         Pure-Python Unicode PST writer (NDB / LTP / messaging layers)
  pst_reader.py         Independent PST parser used for self-verification
  pst_export.py         .eml → PST conversion, splitting, duplicates, verification
  models.py             Mailbox model, settings, DPAPI password storage
  winpower.py           Keeps Windows awake and unthrottled while a download or export runs
native/                 Optional Rust core (PyO3): IMAP download, PST writer, .eml parser, HTML cleanup, PST self-check
  check.py              Compares the native core with the Python code on a real mailbox
tests/                  Automated tests (unittest), fake IMAP server, tricky sample messages
.github/workflows/      CI: tests in both modes, exe build, release on a v* tag
gui/
  account_dialog.py     Mailbox settings dialog
  viewer.py             Built-in message viewer
  export_dialog.py      PST export dialog
  theme.py              Light / dark themes
  fit.py                Table columns that follow the window width, text that ends with "…"
build.bat               Local Windows build script
shinra.spec             PyInstaller build settings (folder build, trimmed Qt, icon, version)
assets/shinra.ico       App icon
```

## Known limitations

- Windows only (the code runs elsewhere, but DPAPI and the packaging target Windows).
- The PST writer creates mail folders and messages. Contacts, calendars and other item types are not part of an IMAP archive and are not written.
- A few optional internal PST tables (receive folder table, outgoing queue) are not created yet. Outlook's Inbox Repair Tool (`SCANPST.EXE`) may report them as missing; this does not affect the archived mail.
- A PST password only prevents opening the file in Outlook's UI. It is **not** encryption.

If Outlook refuses to open a generated file, run `SCANPST.EXE` on a copy of it and attach the generated `.log` to an issue.
