# Shinra Tensei

> English version: [README.md](README.md)

Параллельная архивация нескольких почтовых ящиков по IMAP с экспортом в Outlook PST.
Интерфейс и логика по мотивам MailStore Home/Server.

## Возможности
- Несколько ящиков одновременно (число параллельных загрузок — в панели инструментов).
- Выбор нескольких ящиков галочками (щелчок по заголовку столбца ✔ отмечает или снимает все):
  запуск, экспорт и удаление сразу для всех отмеченных.
- Контекстное меню по правой кнопке: запуск загрузки, экспорт в PST, просмотр писем,
  изменение и удаление ящика.
- Прогресс загрузки в виде «скачано / всего (NN%)».
- Для ящика: e-mail, сервер, порт, протокол (SSL/TLS, STARTTLS, без шифрования),
  «Принимать все сертификаты» (просроченные, самоподписанные, старый TLS), логин, пароль.
- Своя папка для .eml у каждого ящика (или общая папка архива). При смене папки программа
  предлагает перенести уже скачанные письма.
- Период: за всё время или с/по дату.
- Все папки или одна выбранная (кнопка «Загрузить список папок», кириллица поддерживается).
- Ошибка на письме → окно: Пропустить / Пропускать все ошибки ящика / Повторить / Остановить.
  При обрыве связи программа сама переподключается (до 3 раз).
- Докачка: повторный запуск загружает только новые письма.
- Письма запрашиваются у сервера пачками (до 100 писем или 16 МБ за команду), а не по одному.
- Несколько соединений на ящик (поле «Соединений» в настройках ящика, по умолчанию 1): пачки
  писем качаются одновременно, это быстрее на серверах, ограничивающих скорость одного соединения.
- Повторы писем не скачиваются: письмо с тем же Message-ID и размером, что уже есть в другой папке
  ящика (например, «Вся почта» в Gmail), второй раз не загружается. Отключается в настройках ящика.
- Просмотр писем прямо в программе: дерево ящиков и папок, список с датами отправки и получения,
  сортировка, поиск (везде или только по отправителю, получателям, теме, именам вложений; и по
  тексту писем), фильтры по датам, «только с вложениями» и по размеру, предпросмотр (HTML/текст,
  встроенные картинки), сохранение вложений и .eml.
- Интерфейс на русском и английском: переключатель «Язык / Language» на панели инструментов,
  при первом запуске выбирается язык Windows. Даты, числа, имена папок в PST и отчёт — на выбранном языке.
- Темы оформления: Системная (следует за Windows), Светлая, Тёмная — переключатель в панели инструментов.
- Экспорт в PST: отдельный .pst на каждый ящик, структура папок и статус «прочитано» сохраняются.

## Где что лежит
- Архив: `Документы\Shinra Tensei\Archive\<e-mail>\<папки>\*.eml` (можно сменить кнопкой «Папка архива…»).
  При обновлении со старой версии (MailArchiver) настройки переносятся автоматически, а уже скачанный архив остаётся на прежнем месте.
- Настройки: `%APPDATA%\Shinra Tensei\config.json` (пароли зашифрованы Windows DPAPI).
- Журналы: `%APPDATA%\Shinra Tensei\logs\`.

## Экспорт в PST
PST-файл собирается **самой программой** по открытой спецификации Microsoft [MS-PST]
(модули `core/pst_writer.py` и `core/pst_reader.py`). Outlook не нужен — ни запущенный,
ни установленный; файл не подключается к профилю Outlook.

- Отдельный файл на каждый ящик, структура папок сохраняется («INBOX» → «Входящие»).
- Переносятся тема, отправитель, получатели (Кому/Копия), даты отправки и получения,
  текст и HTML, вложения (любого размера), исходные заголовки, статус «прочитано».
- Размер одной части PST задаётся в окне экспорта (0,5–50 ГБ, по умолчанию 10 ГБ); ящики больше
  делятся на части (`_часть2.pst` и т. д.). Письма пишутся по дате получения, поэтому каждая часть
  покрывает непрерывный период.
- Отчёт об экспорте рядом с PST (`<e-mail>_отчёт.txt`): для каждой части — размер, число писем,
  период и список папок с количеством писем и датами «с — по».
- Окно экспорта отдельное: загрузка почты и главное окно работают одновременно с экспортом,
  можно запустить несколько экспортов сразу.
- Журнал во вкладках: «Все» и отдельная вкладка для каждого ящика (туда же пишется ход экспорта).
- Прогресс экспорта: полосы для текущего ящика и для всех выбранных, с количеством писем и процентами.
- Повторы писем (то же письмо в нескольких папках, например «Вся почта» в Gmail) по умолчанию
  не записываются: письмо остаётся в папке по ярлыку, а в «Вся почта» попадают только письма без
  ярлыков. Флажок в окне экспорта; сколько повторов пропущено — в отчёте.
- Пароль на PST: до 15 символов, латиница/цифры/знаки (ограничение Outlook).
  Пароль PST защищает только от открытия через интерфейс Outlook, это не шифрование.
- После записи каждый файл проверяется независимым модулем чтения: контрольные суммы,
  подписи, B-деревья, таблицы и количество писем в каждой папке.

Открыть результат: Outlook → Файл → Открыть и экспортировать → Открыть файл данных Outlook.

## Сборка .exe
Вариант 1 — на Windows: установите Python 3.10+ (python.org, отметьте «Add to PATH»)
и запустите `build.bat`. Готовый файл: `dist\Shinra Tensei.exe`.

Вариант 2 — без Python: загрузите папку в репозиторий GitHub, во вкладке Actions
запустится сборка (сначала автотесты), exe появится в Artifacts.

Выпуск: отправьте метку версии — `git tag v0.13.0 && git push origin v0.13.0`. Actions соберёт exe и
опубликует его во вкладке Releases с описанием изменений из раздела этой версии в CHANGELOG.

### Автотесты
`python -m unittest discover -s tests -t .` — разбор писем (Rust и Python дают одно и то же,
испорченные письма не роняют программу), запись и самопроверка PST, загрузка с тестового
IMAP-сервера (пачки, обрывы связи, капризы серверов, повторы писем), индекс и фильтры
просмотрщика. С `SHINRA_PURE_PYTHON=1` те же тесты проверяют Python-версию. GitHub Actions
запускает их при каждой отправке в обоих режимах.

Запуск из исходников: `pip install -r requirements.txt` → `python app.py`.

### Нативное ядро (Rust, необязательно)
Экспорт в PST может работать на ядре, написанном на Rust (папка `native/`). Оно разбирает `.eml`,
пишет PST и выполняет самопроверку примерно в 6 раз быстрее Python-кода, а несколько экспортов
одновременно действительно занимают несколько ядер процессора. Файлы PST получаются побайтно
такими же, как у Python-версии.

Просмотрщик писем остаётся на Python (PySide6), но индекс папки для него тоже собирает ядро: в
несколько потоков, примерно в 15 раз быстрее.

- GitHub Actions собирает ядро автоматически. `build.bat` собирает его, если установлен
  [Rust](https://rustup.rs), а иначе пропускает.
- Из исходников: `pip install ./native` (нужен Rust).
- Без модуля или с переменной окружения `SHINRA_PURE_PYTHON=1` программа работает на
  Python-коде, как раньше.
- `python native/check.py "<архив>\<e-mail>"` сверяет обе версии на настоящем ящике: разбор писем,
  байты PST и самопроверку.
